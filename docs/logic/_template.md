# Feature area

Replace each prompt below with an Atlas-specific account of the feature before implementing it. Start from documented user-facing capabilities and use behavior studies or fixtures as evidence. Record the owner and delivery phase.

## Purpose

Identify actors, outcomes, scope and upstream documentation.

## Rules

State invariants, defaults, validation, precedence and permission rules.

## Lifecycle and state transitions

Describe initial states, authorized transitions, triggers and durable effects.

## Edge cases

Cover missing data, legacy imports, time zones, locale, limits and concurrent changes.

## Failure modes

Describe retry, rollback, partial failure, idempotency and operator recovery.

## Security

Describe trust boundaries, tenant scope, privacy obligations and abuse controls.

## WordPress and WooCommerce weaknesses

Identify behavior or operational constraints Atlas can improve and explain the trade-off.

## Atlas design

Describe the native API, persistence model, events, adapters and any deliberate replacement.

## Test scenarios

List happy-path, denial, edge, failure and regression cases with observable outcomes.
