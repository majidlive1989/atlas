# Internationalization conventions draft

Use `owner:surface.message-name`, with registered owner namespaces like `core`, `plugin.commerce-cart` and `theme.reference`. The key describes intent. Catalog values use ICU MessageFormat and named typed parameters. Translators receive descriptions and parameter examples. Avoid fragments and string concatenation. Keep markup as explicitly allowed rich-text tokens. CI checks missing keys, plural categories and incompatible parameters. Use BCP 47 locales and Intl for presentation, and keep machine timestamps and API codes stable.

```ts
type MessageKey = `${string}:${string}.${string}`;
type MessageValue = string | number | Date;
type Translate = (key: MessageKey, values?: Readonly<Record<string, MessageValue>>) => string;
```

Use exact locale, language, site default, then base catalog fallback. Record missing keys in development. Update document direction and formatting together on locale change. Use logical CSS rather than direction-specific offsets.
