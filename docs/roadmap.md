# Atlas delivery roadmap

Phase 0 establishes the build and target architecture. Each feature phase begins with behavior studies from the [logic template](logic/_template.md), uses public contracts, and ends with a verified report and tag. The [parity matrix](parity-matrix.md) tracks the assigned outcome for each source capability.

| Phase                      | Scope                                                                                                                                                      | Depends on | Acceptance                                                                                                                                                                                                                                                       |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 · Kernel and identity    | Fastify bootstrap, Zod config and OpenAPI, scoped Postgres migrations, identity and RBAC, typed hooks, plugin lifecycle, operator CLI                      | 0          | Fresh migration and seed give working login, rotation and 2FA. Role policy denies unauthorized access and failed plugin activation or migration rolls back. OpenAPI validates.                                                                                   |
| 2 · Extension platform     | Public SDK, permission and migration interfaces, trusted and sandboxed execution tiers, testkit, generator, signed packaging and example plugins           | 1          | Generated plugin builds. Both examples activate and work against the API. Isolation tests prove undeclared access is denied, and API Extractor records the public surface.                                                                                       |
| 3 · Content foundation     | Content and field types, taxonomies, revisions, media, menus, Postgres search, import/export and content webhooks                                          | 1–2        | Exercise publication, scheduling, trash, restoration, upload variants and permission checks. Import at least 95% of the reference WXR fixture and account for the rest. Verify optimistic conflicts and indexed large lists.                                     |
| 4 · Admin and localization | Design system, admin shell and CRUD screens, extension slots, settings builder, ICU catalogs, RTL, keyboard accessibility                                  | 1–3        | Install a plugin and see its declared admin surfaces. Switch English, Persian and Arabic with zero missing keys. Meet the initial 150 KB gzip budget and dashboard Lighthouse 95.                                                                                |
| 5 · Publishing experience  | Block editor, moderated comments, SEO and feeds, search adapters, forms and mail templates                                                                 | 2–4        | Publish nested blocks, moderate a guest comment, and confirm search, feed and sitemap visibility. Register a third-party block across editor, API and renderer.                                                                                                  |
| 6 · Frontend and themes    | Public contracts, frontend SDK, template resolution, previews, customization and reference themes                                                          | 3–5        | Switch themes and publish a live customization. Authorized draft preview and cache-tag revalidation work. Both themes pass conformance and an alternative frontend consumes public contracts.                                                                    |
| 7 · Commerce               | Catalog, inventory, pricing, cart and checkout, payment gateways, taxes, shipping, orders, refunds, customer accounts, downloads, reporting and storefront | 1–6        | Set up a shop, complete a Stripe test-mode payment, import Woo CSV with a mapping report and verify account and guest workflows, refunds and downloads. Reconcile totals to minor units and prevent oversell under 200 concurrent checkout attempts on 10 units. |
| 8 · Migration tooling      | PHP inventory, native TS scaffolding, optional adapters, machine-readable mapping, safe data import and worked ports                                       | 2–3, 5, 7  | All representative fixtures produce building ports with behavior coverage and truthful reports. CI compares mapping coverage to adapter exports and proves the importer never executes PHP.                                                                      |
| 9 · Production readiness   | Signed updates, recovery and backups, marketplace, multisite operations, security and performance, observability, installer and final parity audit         | 1–8        | Clean installer starts a seeded demo in under 10 minutes. Failure injection verifies rollback and restore without data loss. Tenant isolation, security, performance and release gates pass.                                                                     |

## Risk register

| Risk                                                        | Impact   | Owner and mitigation                                                                                                                                                                    | Evidence gate                                                         |
| ----------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Cross-tenant access through pooled queries or jobs          | Critical | Kernel and DB enforce composite scope, scoped repos and transaction-local row policies. Namespaced cache and job payloads keep background work isolated.                                | Multi-tenant tests from Phase 1, full isolation suite in Phase 9      |
| Untrusted plug-in code inherits host privileges             | Critical | SDK owners isolate code with OS controls, deny ambient credentials, and mediate services through permission-checked RPC. Disable untrusted execution where the boundary is unavailable. | Phase 2 denial and isolation tests                                    |
| Outbox retries duplicate effects or reorder state           | High     | Hooks and kernel use idempotency, aggregate versions and monitored retry queues.                                                                                                        | Phase 1 design and Phase 3 webhook replay tests, expanded in Phase 7  |
| Large imports or media processing block availability        | High     | Content and media use bounded streaming, durable progress, provider limits and recoverable jobs.                                                                                        | Phase 3 fixtures and large-list query plans                           |
| Plugin UI breaks host or increases initial payload          | High     | Admin owns verified lazy loading, error isolation, typed slots and size budgets.                                                                                                        | Phase 4 install and performance gates                                 |
| Editor or template choices lose imported content            | High     | Content, editor and themes version schemas, retain revisions and report lossy transformations.                                                                                          | Phase 3 import, Phase 5 block migration and Phase 6 theme conformance |
| Concurrent checkout overcommits stock or duplicates charges | Critical | Commerce reserves atomically and uses bound idempotency and provider operation keys.                                                                                                    | Phase 7 stress, reconciliation and end-to-end tests                   |
| Money and tax totals diverge across rounding rules          | High     | Commerce keeps minor-unit snapshots, deterministic allocations and property tests.                                                                                                      | Phase 7 rounding and coupon tests                                     |
| Generated ports give unwarranted confidence                 | High     | Migration tools report reviewed confidence, preserve locations, and require manual treatment for dynamic or sensitive behavior.                                                         | Phase 8 fixture and strict-mode gates                                 |
| Updates leave schema and artifacts inconsistent             | Critical | Operators stage verified releases, journal progress and validate restored backups.                                                                                                      | Phase 9 migration and crash failure injection                         |
| Accessibility and translation regress across extensions     | High     | UI and i18n publish conformance checks, keyboard and RTL cases, and locale key gates.                                                                                                   | Phase 4 baseline, Phase 9 full sweep                                  |
| Parity claims exceed verified capabilities                  | High     | Maintain a per-capability owner and milestone, then audit with behavior tests and ADR-backed replacements.                                                                              | Phase 9 final parity report                                           |

## Gaps and additions

| Priority | Addition                                           | Rationale and target                                                                                                                |
| -------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| P0       | Observable request, event and job lifecycles       | Correlate logs and traces early. Add dashboards and SLOs in Phase 9.                                                                |
| P0       | Signed, recoverable upgrades and verified restores | Reduce outage and supply-chain risk. Ship in Phase 9.                                                                               |
| P1       | Forms builder                                      | Add schema-managed forms and submissions without third-party glue in Phase 5.                                                       |
| P1       | Accessibility checker                              | Expose automated findings and a review checklist in admin. Start with Phase 4 CI checks and evaluate editor feedback after Phase 5. |
| P1       | Feature flags                                      | Use scoped, audited rollout flags with explicit expiry policy. Evaluate after operational baselines in Phase 9.                     |
| P1       | Multilingual editorial workflows                   | Coordinate translations and locale fallbacks with public hreflang in Phase 6. Evaluate role-specific translation review later.      |
| P2       | Preview environments and content releases          | Evaluate scheduled cross-resource publish sets and checks after staged deployments are stable.                                      |
| P2       | Adapter health and capacity views                  | Expose queue lag, search freshness, storage health and provider error rates in Phase 9 Site Health.                                 |
